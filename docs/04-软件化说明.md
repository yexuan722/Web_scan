## 1. 为什么界面用 Web 技术、外面套一层窗口

不是偷懒，是取舍：

| 形态 | 界面能力 | 打包体积 | 常驻能力 | 开发成本 | 结论 |
| --- | --- | --- | --- | --- | --- |
| **本地 Web（本方案）** | 强（ECharts/表格/实时刷新） | 50 MB | 天然适合 7×24 | 低 | ✅ 选它 |
| PyQt / PySide | 中 | 大 | 一般 | 高 | 图表和布局都要手写 |
| Tauri | 强 | 小 | 好 | 中高 | 要 Rust 工具链 |
| Electron | 强 | 150 MB+ | 好 | 中 | 太重 |

用户感知上没差别：双击 exe → 托盘出现图标 → 浏览器自动打开界面 → 关掉浏览器进程还在，点托盘图标又能打开。

**代价**：任务管理器里能看到一个 HTTP 服务。所以必须做本地访问保护（见 §3）。

## 3. 本次踩的两个坑（诊断记录）

### 坑 1：onefile 在 %TEMP% 解压失败

```
[PYI-92748:ERROR] Could not create temporary directory!
```

单文件模式启动时要把自己解压到 `%TEMP%\_MEIxxxx`，这台机器上被拒绝（杀软/权限），
进程直接退出。**处置**：改 onedir。附带好处是启动更快、误报更少、日志更好查。

### 坑 2：双击没反应，进程 1 秒就退出，退出码还是 0

这是最坑的一个，因为**窗口程序没有控制台，报错完全看不见**。

**定位过程**：
1. 先编一个 `console=True` 的等价包（`webscan-debug.spec`），把异常打到控制台；
2. 得到真实堆栈：

```
File "webscan\api.py", line 61, in <module>
    store = Store()
File "webscan\storage.py", line 64, in __init__
    self.path.parent.mkdir(parents=True, exist_ok=True)
PermissionError: [WinError 5] 拒绝访问。: 'C:\Users\<用户名>\AppData\Local\WebScan'
```

3. 再排除环境因素：Smart App Control 已关、Defender 受控文件夹访问已关；
   用 WMI 绕过当前进程树重新拉起，仍然失败 → 不是我们这次调试的沙箱问题，是**这个 exe 写不了用户目录**；
4. 但同一台机器上 `python.exe` 能往同一个路径写 → 限制只针对这个新编译的、未签名的 exe。

**根因**：`Store()` 在**模块导入期**就建库，数据目录不可写 → 导入异常 → 窗口版无输出 → 静默退出 0。
在正常桌面双击（不在 agent 环境里跑）大概率不会遇到；但只要目标机器上 `%LOCALAPPDATA%` 不可写
（组策略、漫游配置、杀软拦截），任何用户的软件都会这么"死"。

**修复两条**：
- 数据目录三级回落，先试 exe 同级（便携），再试用户目录，最后临时目录，每个都**真写一次文件**验证；
- `Store` 改成懒加载，并把启动异常转成弹窗，至少让用户看到"为什么打不开"。

```python
# config.py
candidates = [exe_dir / "data", LOCALAPPDATA / "WebScan" / "data", TEMP / "WebScan" / "data"]
DATA_DIR = next((p for p in candidates if _writable(p)), candidates[0])
```

### 坑 3：双击后弹「Microsoft Edge 未响应，因为现有实例正在以提升的权限运行」

**现象**：程序双击后，浏览器没打开，反而弹出一个 Edge 的权限对话框。

**原因**：不是扫描器的问题，是 Windows 的 UIPI（用户界面特权隔离）。
浏览器策略是「同一个用户只保留一个浏览器实例」，
如果**已经有一个以管理员权限运行的 Edge**，普通权限的进程再请求打开 URL 时，
Edge 就拒绝把请求交给提权实例，弹出这个框问你要不要降权重启。

触发路径：程序已经在运行（比如托盘里有），用户又双击了一次 →
单实例逻辑调用 `webbrowser.open()` → 撞上提权的 Edge。

**修复**：
1. 打开浏览器前先判断自己是否提权（`IsUserAnAdmin`）；提权时不用 `webbrowser`，
   改用 `explorer.exe <url>` 交给外壳（外壳永远跑在普通权限），避免把权限带进浏览器；
2. 打开失败时不再静默，弹窗把地址摆出来，让用户手动访问；
3. 托盘提示里带上完整地址，随时可以照着手打。

**给用户的建议**：不要用"以管理员身份运行"启动本程序；如果已经弹了那个框，
把 Edge 全部关掉（任务管理器结束所有 `msedge.exe`）再试，或直接手动访问
`http://127.0.0.1:8770/`。

**教训**：这类"只有在真实桌面会话里才会出现"的问题，靠 headless 截图是测不出来的。
自动化测试覆盖了服务端、接口、界面渲染，但"双击之后到底发生了什么"这一环，
必须真人用真实浏览器点一次。

### 坑 4：打包后窗口一片空白（Chromium 渲染进程起不来）

**现象**：源码运行 `python -m webscan` 窗口正常；打包成 exe 后窗口能出来，
但内容区全黑/全白，也没有任何报错；进程列表里**找不到 `QtWebEngineProcess.exe`**。

**诊断过程**：
1. 用 `console=True` 编一个同样的包，把 Qt/Chromium 的日志打到控制台；
2. 看到关键两行：
   ```
   [INFO] web_contents_delegate_qt.cpp:299] ProcessGone: 7 (18)
   [VERBOSE] NetworkDelegate::NotifyBeforeURLRequest: http://127.0.0.1:8770/
   ```
   导航已经开始，但渲染进程刚拉起就死；
3. 对比开发态与打包态：Qt 版本相同、资源（`icudtl.dat`、`*.pak`）都在、
   关键 DLL 齐全 → 排除资源缺失；
4. 用 `--single-process` 试运行：**画面出来了**。说明问题在"子进程启动"这一环；
5. 只加 `QTWEBENGINE_DISABLE_SANDBOX=1`：渲染进程正常拉起、页面正常显示。

**根因**：打包后 Chromium 的沙箱子进程（`QtWebEngineProcess.exe`）无法启动
（沙箱初始化失败被静默吞掉），多进程模式下页面就永远是空白。

**修复**：在 `window.py` 里、**导入 QtWebEngine 之前**设置
`QTWEBENGINE_DISABLE_SANDBOX=1`。只加载本机 `127.0.0.1` 的自家页面，
不渲染任意外部内容，这个折中可以接受；如果将来要在这个窗口里打开外部链接，
就必须改回沙箱模式并解决子进程启动问题。

**教训**：打包类问题，先想办法把 stderr 弄出来（console 版），比盯着白屏猜快十倍。

## 5. 杀软误报（PyInstaller 的老问题）

未签名的 PyInstaller 产物，360/火绒/Defender 有一定概率报"可疑程序"，原因是被打包的
Python 解释器 + 自解压行为长得像恶意软件。

缓解手段（按性价比排序）：
1. 用 **onedir** 而不是 onefile（已在用）；
2. 加版本信息（`--version-file`）和公司名，别留空；
3. 代码签名（最有效，但要花钱）；
4. 分发时附上 SHA256 和源码地址，让用户自行核对；
5. 申请厂商白名单（360/火绒都有开发者申诉通道）。
