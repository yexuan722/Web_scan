## 1. 交付范围

| 需求 | 实现 | 验证方式 |
| --- | --- | --- |
| 输入网址自动扫描 | Web 界面 + CLI 两条入口 | 靶站实测 |
| 爬取站点结构 | 同源 BFS，链接/表单/参数抽取 | 8 页靶站全部抓到 |
| 漏洞分析 | 被动规则 10 类 + 只读探测 + 主动 PoC 4 类 | 靶站 13 条命中 |

| 可视化界面 | 本地 Web UI（零构建链） | 截图验证 |
| 做成软件 | 纯标准库服务层 + 静态前端，可 PyInstaller 打包 | 构建脚本就绪 |

├── api.py           标准库 HTTP 服务（无 FastAPI/uvicorn）
├── cli.py           命令行入口
├── rules/
│   ├── passive.py   只看已有响应（零请求、零风险）

## 3. 已实现的规则

### 被动规则（不需要额外请求）

| rule_id | 判定依据 | 严重度 |
| --- | --- | --- |
| `SEC-HEADERS` | 缺少 CSP / nosniff / X-Frame-Options / Referrer-Policy / Permissions-Policy | 取缺失项最高 |
| `CSP-WEAK` | CSP 含 `unsafe-inline` / `unsafe-eval` / `*` | 中 |
| `HSTS-MISSING` | HTTPS 站点无 `Strict-Transport-Security` | 低 |
| `COOKIE-FLAGS` | Set-Cookie 缺 Secure / HttpOnly / SameSite | 中/低 |
| `BANNER` | Server / X-Powered-By 含版本号 | 低 |
| `DIR-LISTING` | 页面为目录索引 | 中 |
| `ERROR-DISCLOSURE` | 响应含堆栈/数据库报错特征 | 中 |
| `HTML-COMMENT` | 注释含口令线索、内网 IP、密钥字段 | 低 |
| `MIXED-CONTENT` | HTTPS 页面引用 HTTP 资源 | 中 |
| `FORM-CLEARTEXT` | 密码表单提交到 HTTP | 高（HTTPS 降级）/ 中 |
| `FORM-GET-PWD` | 密码字段用 GET 提交 | 中 |
| `SOURCE-MAP` | 响应含 `sourceMappingURL` | 低 |

### 只读探测

| rule_id | 判定 | 误报控制 |
| --- | --- | --- |
| `SENSITIVE-PATH` | `.git/config`、`.env`、`backup.zip` 等 17 条路径 | **内容指纹全匹配**才算数（避免把 404 页面当泄露） |
| `CORS-REFLECT` | 伪造 Origin 被原样回显 | 再判断是否 `Allow-Credentials` |
| `CORS-WILDCARD` | `Access-Control-Allow-Origin: *` | 低危 |

### 主动 PoC（默认关闭）

| rule_id | 载荷 | 验证条件 |
| --- | --- | --- |
| `XSS-REFLECT` | `<script>alert('ws7f2a')</script>` | 完整载荷原样出现在响应中，且响应非 3xx |
| `SQLI-ERROR` | `'` / `"` / `')` | 报错特征命中 **且** 基线无该报错 **且** 换第二个载荷可复现 |
| `LFI` | `../../../etc/passwd` 等 2 条 | 系统文件特征串命中，且基线无 |
| `OPEN-REDIRECT` | `//ws-evil.example/landing` | 3xx 且 Location 指向外部域 |

**三条硬约束**：
1. 只发 GET，测试前会给参数"追加"载荷，不覆盖原有值（除 LFI 需要整段替换）。
2. 跳转一律 `follow=False`，避免把 A 接口的注入打到 B 接口上（这个坑实测踩过一次，见第 6 节）。
3. 没有 evidence 的发现不产出。

## 4. 评分模型

```
p_i = base[severity] × confidence
P   = 1 - Π(1 - p_i)
score = round(100 × (1 - P))
```

`base = {critical 0.35, high 0.20, medium 0.08, low 0.02, info 0}`。

单测锁定：空站点 100 分；单个 critical（置信度 1.0）必须是 65 分；info 不扣分。

## 5. 靶站实测

靶站 `labs/vuln_app.py` 预置 6 类漏洞 + 若干配置缺陷。

一次完整扫描（deep 模式）结果：

| 指标 | 数值 |
| --- | --- |
| 抓取页面 | 8 |
| HTTP 请求 | 66 |
| 耗时 | 11 s |
| 发现总数 | 13 |
| 已验证 | 11 |
| 健康评分 | 10 / 100（危险） |

检出清单（全部为真阳性，与靶站预置漏洞一一对应）：

```
严重  LFI / 路径穿越        /download?file=../../etc/passwd
严重  Git 配置泄露          /.git/config
严重  环境变量泄露          /.env
严重  SQL 注入（错误型）    /item?id=1'
高危  反射型 XSS            /search?q=<script>...
中危  开放重定向            /redirect?next=//ws-evil.example
中危  Cookie 属性缺失       session
中危  目录浏览              /files
中危  登录页未启用 HTTPS    /login
中危  密码字段 GET 提交     /login
中危  安全响应头缺失        /
低危  版本信息泄露          Server: ACME-Server/1.2.3
低危  注释残留开发标记      <!-- TODO: 删掉测试账号 ... -->
```

**漏报**：靶站的 `/debug`（堆栈泄露）没有链接入口，爬虫发现不了 —— 这属于"不可达页面"的固有局限，
不是规则问题，报告里如实写。

## 6. 实测中修掉的两个误报

### 误报 1：跳转链路导致的 SQL 注入假阳性

- 现象：`/redirect?next=/item?id=2` 被判成 SQL 注入。
- 原因：探测时 `follow_redirects=True`，参数被追加 `'` 后服务端跳到 `/item?id=2'`，
  报错来自**下游接口**，与 `next` 参数无关。
- 修复：所有主动探测改为 `follow=False`，3xx 直接放弃判定。
- 教训：跨接口的"证据"不算证据。

### 误报 2：版本泄露重复上报

- 现象：Server 与 X-Powered-By 各报一条，同一主机刷出两条低危。
- 修复：把版本泄露从"按页"上移到"按主机聚合"，多条头合并成一条。

这两条正好可以写进报告的"误报分析与处理"章节。

## 7. 已知限制（v1 明确不覆盖）

| 限制 | 影响 | 计划 |
| --- | --- | --- |
| 只测 GET 参数与 GET 表单 | POST 注入点全部漏掉 | v1.1 加 POST 表单（需逐字段确认无副作用） |

| 单目标串行 | 无批量资产扫描 | v2 |

## 8. 如何验证

```powershell
# 1) 起靶站
powershell -File scripts\run_lab.ps1 -Port 8899

# 2) 命令行扫一次（另开一个窗口）
python -m webscan --scan http://127.0.0.1:8899/ --deep

# 3) 或打开图形界面
powershell -File scripts\run.ps1 -Port 8770
#    浏览器访问 http://127.0.0.1:8770/

# 4) 单元测试
python -m unittest discover -s tests -v
```

> 端口 8870/8765 之类的常见端口可能已被其他服务占用（本机 8765 就被另一个常驻程序占着）。
> 启动时若提示端口占用，换 `--port` 即可。
