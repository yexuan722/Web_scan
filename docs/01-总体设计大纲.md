# 总体设计大纲

> 项目：WebScan 1.0 —— Web 漏洞扫描 + 实时监控响应
> 日期：2026-10-29
> 状态：设计稿 v0.1（待决策确认）

---

## 0. 一句话定位

**一台机器上跑的单体软件**：本地 Web 界面 + 两个引擎（主动扫描引擎、被动监控引擎），
共享规则库、证据库、事件模型与报表，可打包成 exe，7×24 挂着守一个自己有权管的站点。

不做"公网随便扫"的产品，只做**授权范围内**的检测与被监测资产的防护。

---

## 1. 范围拆解：这其实是两个系统

课程 30（扫描系统）和 54（监控响应系统）共用"输入网址 → 出结论"的表皮，
但引擎层面的假设几乎是相反的：

| 维度 | 扫描子系统（课题 30） | 监控子系统（课题 54） |
| --- | --- | --- |
| 数据来源 | **主动**发请求、自己爬 | **被动**收日志/流量，别人的请求 |
| 视角 | 攻击者视角，黑盒 | 防守者视角，需要能看见请求 |
| 时间性质 | 一次性、可离线、几分钟到几小时 | 持续、秒级、不能断 |
| 覆盖对象 | 目标站点的**表面攻击面** | 经过该资产**全部访问行为** |
| 正确性标准 | 漏洞是否真实（可复核 PoC） | 告警是否及时、误报是否可忍 |
| 阻断能力 | **没有**，扫描器不能挡攻击 | 有，但必须有明确的阻断点 |

**结论**：共用 UI / 规则元数据 / 证据存储 / 报表导出，但**引擎必须分开**，
各自有独立的进程内模块与测试集。硬把两者揉成一个"循环扫描器"是后面所有设计问题的根。

## 2. 部署形态与阻断点（必须三选一）

"应急阻断攻击"这句话只有在**流量经过本软件**或**本软件能改防火墙/网关策略**时才成立。
一个黑盒扫描器没有任何阻断点。三种可选形态：

### 模式 A：反向代理模式（推荐的演示/验收形态）

```
浏览器 → 本软件:8000 (反向代理+检测+阻断) → 被测站点:8080
```

- 看得见：完整请求/响应、Body、Header、Cookie、状态码、耗时、上游错误。
- 能检测：注入、XSS、爆破、扫描器指纹、异常速率、5xx 突增。
- 能阻断：请求级拦截（返回 403 拦截页）或按 IP 临时封禁，**毫秒级，可回滚**。
- 代价：只保护**挂在代理后面**的站点；需要处理流式响应、大文件、WebSocket 透传。
- 实现：`aiohttp`/`Starlette` 写一个轻量反向代理即可，几百行，演示效果最好。

### 模式 B：日志侧车模式（贴近生产）

- 采集 nginx/Apache/IIS 访问日志（`tail -F` 跟随轮转），也可读应用 JSON 日志。
- 能检测：同 A 的大部分（缺少响应体，XSS/SQLi 只能靠请求侧特征，误报略高）。
- 能阻断：通过 nginx `deny` + reload、`iptables`/`netsh advfirewall`、fail2ban。
  **注意**：Windows 上改防火墙需要管理员权限，演示时不优雅。
- 推荐做成 v1 的"第二适配器"，证明采集层是抽象的、可替换的。

### 模式 C：纯黑盒外部监测（能力必须诚实标注）

- 只能看到：站点是否可访问、响应时间、状态码、证书到期、页面内容是否被篡改。
- **完全无法**检测 SQL 注入/XSS 等攻击行为——看不到攻击者的请求。
- 不能阻断，只能"发现了再通知你去处理"。
- 定位：**可用性与完整性监测**，作为监控子系统的降级形态，不能当卖点。

| 形态 | 看得到攻击 | 能阻断 | 部署难度 | 演示效果 |
| --- | --- | --- | --- | --- |
| A 反向代理 | ✅ 完整 | ✅ 毫秒级 | 低 | ★★★★★ |
| B 日志侧车 | ⚠️ 仅请求侧 | ✅ 秒级 | 中 | ★★★★ |
| C 黑盒外部 | ❌ | ❌ | 极低 | ★★（仅可用性） |

**建议**：A 作为默认演示路径，B 作为架构扩展证明，C 降级为"资产可用性心跳"，
在报告里明确定义为不同能力等级（Capability Level 1/2/3），这本身就是加分项。

```
┌────────────────────────── Web UI（浏览器，仅监听 127.0.0.1）──────────────────────────┐
│ 资产/授权台 │ 扫描向导 │ 扫描报告 │ 实时监控大屏 │ 事件中心 │ 响应模板 │ 设置            │
└────────────────────────────────────┬───────────────────────────────────────────────────┘
                                     │ HTTP + WebSocket（实时推送）
┌────────────────────────────────────▼───────────────────────────────────────────────────┐
│                        API 层（FastAPI）：鉴权 · 审计 · 限流 · 任务接口                 │
├───────────────────────────┬──────────────────────────────┬────────────────────────────┤
│  扫描子系统（主动）        │  监控子系统（被动）            │  公共域                    │
│  ├ 任务调度 / 队列         │  ├ 采集适配器（proxy / tail）  │  ├ 规则库 + 版本管理        │
│  ├ 爬虫 + 会话管理         │  ├ 解析器 + **归一化**         │  ├ 健康评分引擎            │
│  ├ 被动规则（无 payload）  │  ├ 检测规则引擎                │  ├ 事件状态机 + 聚合去重    │
│  ├ 主动 PoC + 验证器       │  ├ 基线/速率异常检测           │  ├ 告警分发（多渠道）       │
│  ├ 证据采集（req/resp）    │  └ 阻断决策器                  │  ├ 阻断执行器（可回滚）     │
│  └ 报告与评分              │                               │  ├ 溯源时间线              │
│                            │                               │  └ 审计日志                │
└───────────────────────────┴──────────────────────────────┴────────────────────────────┘
                                     │
              SQLite（WAL）+ 证据文件（压缩包）+ 配置（YAML）
```

**分层原则**：`core/` 是与 UI 无关的纯 Python 库，可被单元测试和 CLI 直接调用；
`api/` 只做参数校验与编排；`web/` 只做展示。这条线守住了，项目才可测、可写进报告。

## 4. 扫描子系统

### 4.1 任务与授权前置

每次扫描必须绑定一个**资产记录**，资产记录必须有：

- `target`：域名或 IP（强制 scheme + host）
- `ownership`：授权方式（自建靶场 / 书面授权 / 内置靶场白名单）
- `authorized_at`、`authorized_note`、`scope`（允许的路径前缀、排除路径）
- 未绑定授权的任务**在 UI 层直接拒绝**，不是弹个"你确认吗"就放行。

这既是合规，也是课程报告里"系统设计"的亮点：把法律边界做成产品特性。

### 4.2 爬虫设计

| 问题 | 方案 |
| --- | --- |
| 站点范围 | 默认同源（scheme+host+port），可配子域；`scope.exclude` 强制排除 |
| 破坏性 URL | 关键词黑名单（logout/delete/remove/update/pay/cancel）+ 只对 GET 自动爬 |
| 会话态 | 支持登录流程（表单/JSON 两种录制），Cookie Jar + CSRF token 自动回填 |
| 去重 | URL 规范化（排序 query、去 fragment、strip 默认端口）+ 内容指纹（正文 simhash） |
| 爬虫陷阱 | 深度上限、URL 数上限、同模式路径折叠（`/page/1`、`/page/2`... 合并） |
| 速率 | 全局 RPS 上限 + 每主机并发上限，默认 5 rps（礼貌且不易被 WAF 拦） |
| SPA | 默认 httpx 只抓静态 HTML；`--render js` 启用 Playwright 渲染分支 |
| 发现面 | `<a href>`、`<form>`、`<script src>`、`fetch/XHR` 字面量、`sitemap.xml`、`robots.txt` |

**输出物**：`urls` 表（含 method/参数名/表单结构）+ 每个 URL 的原始响应快照。
爬完之后再做规则分析，**爬虫不碰 payload**。

### 4.3 被动规则（无 payload，只读，零风险）

- 安全响应头：CSP、HSTS、X-Frame-Options/frame-ancestors、X-Content-Type-Options、Referrer-Policy
- Cookie 属性：Secure / HttpOnly / SameSite
- TLS：协议版本、证书有效期、弱套件（`ssl` 模块 + `sslyze` 可选）
- 信息泄露：Server/X-Powered-By 版本、堆栈报错、`.git/.svn/.env/.DS_Store`、
  目录列表、source map、备份文件、`phpinfo`、`/actuator/*`、调试头
- CORS：`Access-Control-Allow-Origin` 反射 + `Allow-Credentials: true` 组合
- 前端：混合内容、密码框 `autocomplete`、注释里的内网地址/账号
- 敏感路径：受控字典探测（限 200 条内置，禁止外挂大字典以免变成爆破）

### 4.4 主动 PoC（强授权 + 只读探测 + 二次验证）

| 类别 | 探测方式 | 验证条件 | 风险 |
| --- | --- | --- | --- |
| 反射型 XSS | 注入唯一 token `ws7f2a`，看是否**未编码**回显在 HTML 上下文 | token 出现在可执行上下文（非属性值/非注释）且字符未被转义 | 低 |
| SQL 注入（错误型） | 参数追加 `'`、`")`，比对报错特征 | 报错含 DB 特征串，且**去掉 payload 后不复现** | 低 |
| SQL 注入（布尔型） | `AND 1=1` vs `AND 1=2` 两次响应比对 | 响应长度/正文哈希差异稳定（重复 2 次一致） | 低 |
| 路径穿越 / LFI | `?file=../../../../etc/passwd`（Windows 用 `C:\Windows\win.ini`） | 响应含 `root:x:0:0` / `[fonts]` 特征 | 低 |
| 开放重定向 | `?next=//ws-verify.test` | 302 的 `Location` 指向外域 | 低 |
| 默认口令 | 内置 20 组弱口令，仅对登录表单 | 登录成功判定（跳转/关键字） | 中，需显式开关 |
| SSRF | 需要带外回连（interactsh 类） | 回连命中 | 中，v2 再做 |

**每条主动规则的执行契约**：

```
preflight（找注入点）→ 基线请求（存证据）→ 注入请求（存证据）→ 验证（再发一次确认可复现）
→ 命中 → 生成 finding（含 evidence_id、payload、复现步骤）→ 不命中 → 丢弃
```

没有 evidence 的 finding 一律不展示（这是"可复核"的底线，也是答辩时最硬的东西）。

### 4.5 报告与评分

见第 6 节评分模型。报告导出：HTML（含证据截图/报文片段）+ JSON + Markdown。

## 5. 监控子系统

### 5.1 采集适配器接口

```python
class Collector(Protocol):
    def stream(self) -> Iterator[RawEvent]: ...   # 阻塞迭代，天然支持背压
```

- `ProxyCollector`：ASGI 中间件拦截请求，构造 RawEvent 后放行或拦截。
- `LogTailCollector`：`tail -F` + 轮转检测（inode/position 持久化）+ 多行合并。
- `HeartbeatCollector`：定时 HEAD/GET 探活，产生可用性事件。

### 5.2 解析与归一化（**最容易被忽略、又最关键的一层**）

攻击者的绕过主要发生在编码上。检测前必须做**多重解码归一化**，否则规则形同虚设：

1. URL 解码（`%2e%2e%2f` → `../`），最多 3 层
2. HTML 实体解码（`&lt;script&gt;` → `<script>`）
3. Unicode/全角归一化（`＜script＞` → `<script>`）
4. SQL 空白与注释折叠（`union/**/select`、`union%0aselect`）
5. 大小写归一（保留原文供展示，归一化副本供匹配）
6. 超长请求截断（>64KB 只匹配前段，标记 truncated）

每条规则在**归一化文本**上匹配，但展示时回显**原始报文**。
这一层的单元测试单独写，是报告里"检测算法"章节的主要素材。

### 5.3 检测规则（v1 清单）

| 规则 | 判据 | 严重度 |
| --- | --- | --- |
| SQLi 尝试 | union select / information_schema / sleep( / benchmark( / `' or '1'='1` | 高 |
| XSS 尝试 | `<script`、`onerror=`、`javascript:`、`<svg onload` | 高 |
| 路径穿越 | 归一化后含 `../` 且路径中出现连续 3 段以上 | 高 |
| 命令注入 | `;`、`&&`、`|`、`$(...)`、反引号 出现在参数值首尾 | 高 |
| 扫描器指纹 | UA 黑名单（sqlmap/nikto/nmap/masscan/zap）+ 404 突增 | 中 |
| 目录爆破 | 单 IP 5 分钟内 404 > 30 次或访问路径 > 50 个不同路径 | 中 |
| 暴力破解 | 同 IP 同账号 5 分钟内登录失败 ≥ 5 次 | 高 |
| 敏感路径探测 | `/.env`、`/wp-admin`、`/phpmyadmin`、`/.git/config` | 中 |
| 异常速率 | 单 IP 每 10s 请求数 > 基线 3σ 且绝对量 > 50 | 低 |
| 5xx 突增 | 5 分钟窗口 5xx 比例 > 20% 且样本 > 20 | 中 |

### 5.4 事件状态机与聚合去重

```
detect → aggregate(窗口内同规则同源合并) → incident OPEN → notify
      → [auto-block if enabled] → monitor → CLOSE(手动/超时)
```

- **聚合键**：`(rule_id, src_ip, target)`，5 分钟窗口，计数累加，保留首末次与样本报文。
- **抑制**：同一 incident 在 `suppress_window`（默认 30 分钟）内不重复告警，
  只更新计数。没有这一步，一次 SQL 注入扫描能给你发 200 封邮件。
- **溯源时间线**：incident 详情页按时间轴列出命中请求（方法/路径/参数/规则/响应码），
  攻击路径 = 同一源 IP 的请求序列，按会话聚合，附地理/ASN 信息（离线库或跳过）。
- **处置记录**：每次人工/自动动作（封禁、解封、标记误报、升级）写入 `incident_actions`，
  可回看、可导出——对应"支持后续溯源与优化"。

### 5.5 告警

| 渠道 | v1 | 说明 |
| --- | --- | --- |
| Web 弹窗 / 大屏 | ✅ | WebSocket 推送，最高优先级 |
| 邮件（SMTP） | ✅ | 支持聚合摘要，避免刷屏 |
| Webhook（钉钉/飞书/Server酱） | ✅ | 30 行代码，实用 |
| 短信 | ⚠️ | 需第三方服务与费用，做成适配器 + Mock，报告里说明 |
| 桌面系统通知 | 可选 | Windows Toast，需额外依赖 |

分值映射：高危 → 立即推送；中危 → 5 分钟聚合推送；低危 → 每日摘要。

### 5.6 阻断与回滚（**只在模式 A/B 可用**）

- 三种策略：`observe`（只记录，默认）/ `auto`（自动封禁）/ `manual`（等人工确认）。
- 封禁维度：IP、IP+路径、URI 特征。TTL 默认 15 分钟，自动到期解封。
- **必须有的安全阀**：
  - 白名单（内网段、127.0.0.1、自己的扫描器出口 IP）永远不封
  - 单次批量封禁上限（防规则 bug 把你自己的用户全封了）
  - 一键全量解封
  - 每次动作写审计（谁、何时、依据哪个事件、生效多久）
  - **fail-open**：代理内部异常时放行请求，不能让防护把自己站点搞挂
- 明确写进报告的局限：IP 封禁会误伤 NAT/代理后面的正常用户；只能防"低级攻击"，
  不能替代补丁。

## 6. 健康评分模型（可解释，别拍脑袋）

**问题**：现在"给个健康评分"没有定义，答辩必被追问"80 分怎么来的"。

**方案**：noisy-OR 合成模型（假设各漏洞被独立利用）。

```
每个 finding：p_i = severity_base[sev] × confidence
  severity_base = {critical: 0.35, high: 0.20, medium: 0.08, low: 0.02, info: 0.0}
风险概率 P = 1 - Π(1 - p_i)        # 漏洞越多，风险趋近 1，天然递减边际
健康分 = round(100 × (1 - P))
```

示例：1 个高危 → 80；2 个高危 → 64；1 高危 + 3 中危 → 65；只有 5 个低危 → 90。

配套要求：

- 报告里列出**每条扣分**（哪个 URL、哪条规则、扣了多少），分数可复算。
- 分档：90-100 良好 / 75-89 一般 / 50-74 风险 / <50 危险。
- 敏感度分析：把 confidence 全设为 1 再算一次，报告两列对比，说明未验证项的影响。

## 8. 应急响应模板（对应课题 54 第 3 点）

模板是**结构化数据**而不是一段文字，才能"step-by-step 执行 + 记录 + 迭代"：

```yaml
id: data-leak
name: 疑似数据泄露
triggers: [敏感路径探测, 大批量 200 响应, 异常下载速率]
steps:
  - order: 1, title: 确认范围, action: 查该 IP 全部请求与响应码,
    tool: 事件时间线, checkpoint: 是否真的拿到数据
  - order: 2, title: 立即阻断, action: 封禁 IP + 下线可疑接口,
    tool: 阻断模块, checkpoint: 复测是否 403
  - order: 3, title: 评估影响, action: 统计泄露字段与条数, ...
  - order: 4, title: 修复与验证, ...
  - order: 5, title: 复盘归档, ...
```

- 每个 step 有 `checkpoint`（完成判据）和 `记录`（实际做了什么、耗时）。
- 处置完成后可"沉淀"：把实际耗时/额外步骤写回模板，模板带 `version`，
  对应"支持应急响应流程优化"。

## 9. 技术栈

| 层 | 选型 | 理由 |
| --- | --- | --- |
| 语言 | Python 3.11+ | 要求指定，异步生态够用 |
| Web 框架 | FastAPI + Uvicorn | 顺手拿到 WebSocket、OpenAPI 文档 |
| 前端 | Jinja2 + HTMX + ECharts | 免 Node 构建链，PyInstaller 打包最省事；图表够用 |
| 数据库 | SQLite（WAL）+ SQLAlchemy | 单机零运维 |
| HTTP | httpx.AsyncClient | 支持 HTTP/2、连接池、超时控制 |
| HTML 解析 | selectolax（快）/ bs4（兜底） | |
| 渲染爬取 | Playwright（可选依赖） | 打包体积 +300MB，做成可选安装 |
| 调度 | APScheduler | 周期扫描 |
| 打包 | PyInstaller one-folder | 首次启动建 `%LOCALAPPDATA%\WebScan\data` |
| 测试 | pytest + pytest-asyncio | 规则单测 + 靶场集成测试 |

**"做成一个软件"的落地方式**：单个 exe → 启动时拉起本地服务（127.0.0.1 随机高位端口）
→ 自动打开默认浏览器 → 托盘常驻。这是最省事、跨平台、还可远程（加开关）的形态。
比 PyQt 更适合 7×24 常驻和实时图表。

## 11. 评测方案（报告的核心素材）

在自建靶场上做，产出可量化指标：

1. **漏洞检出**：靶场预置 12 个已知漏洞（每类 2 个），统计 TP / FN / FP，算精确率与召回率。
2. **误报率**：对同一个正常站点（无漏洞的静态站）扫 10 次，记录误报条数。
3. **监测时效**：注入一次攻击 → 从请求到达至告警弹出的延迟（记录 p50/p95）。
4. **阻断时效**：从命中到 403 生效的延迟。
5. **吞吐**：代理模式下的 QPS 损耗（开着检测 vs 关着检测）。
6. **绕过测试**：用编码变体（`%2e%2e%2f`、大小写混写、注释插入）测试归一化是否生效，
   记录漏检率——这条最能体现深度。

## 12. v1 明确不做

- 端口扫描 / 服务爆破（超出 Web 语义层，且极易越界）
- 漏洞利用（getshell、提权、数据导出）——只到"证明存在"为止
- 绕过 WAF 的对抗性 payload 混淆
- 分布式多节点扫描、大规模并发
- 移动端 App 逆向、API 全量 fuzz
- 短信网关真实对接（用适配器 + Mock 代替）
