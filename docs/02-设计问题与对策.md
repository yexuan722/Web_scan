# 设计思路漏洞清单

> 对照 `web_scan1.0.txt` 的原始需求逐条挑毛病。按"会不会把项目做废"排序。
> 每条的格式：**症状 → 后果 → 对策**。

---

## 🔴 致命级：不改，项目方向就错了

### 1. 把"监控"理解成了"反复扫描"

**原话**：「可长期挂在某个指定网站上面持续扫描该网站，出现异常情况或者高风险情况即时传达警报」

**症状**：这句话假设"我一直扫它，就能发现它在被攻击"。

**为什么错**：
- 扫描是**我发请求**，监控要的是**看别人发的请求**。两码事。
- 你对着别人网站扫一万遍，也看不到黑客对它的 SQL 注入——那是它服务器上的日志，
  你不在链路上。
- 持续扫描第三方站点会让对方 IDS 把你当攻击者，这不是"监控"，这是"骚扰"，
  而且本身就是未授权扫描，法律风险跑不掉。

**后果**：功能二做出来只会变成"每隔 5 分钟扫一次，然后看到分数变了"，
既检测不到攻击，也谈不上响应，答辩一问就穿。

**对策**：监控必须换数据源。选一个：
- **反向代理**（流经本软件的流量）→ 能看全，能秒级阻断，演示最佳
- **日志侧车**（读 nginx/Apache 日志）→ 贴近生产，只能看请求侧
- 纯黑盒探活 → 只能测可用性和篡改，**必须诚实标注**"无法检测攻击"

三条路的取舍写在 `01-总体设计大纲.md` 第 2 节。

---

### 2. "应急阻断攻击"没有明确的阻断点

**原话**：「拥有应急阻断攻击的能力（可在软件控制面板开关）」

**问题**：一个外部扫描器/监控器**没有任何办法阻断攻击**。攻击者不经过你，
你拿什么断？给人家网站打补丁？调它的防火墙？

**对策**：阻断能力必须绑定部署形态：
- 代理模式：请求级拦截 + IP 封禁，毫秒级，可回滚（推荐）
- 日志模式：下发 nginx deny / 防火墙规则，秒级
- 黑盒模式：**没有阻断**，只能告警

并且要加安全阀：白名单、TTL 自动解封、单次封禁上限、一键全解、**fail-open**、
操作审计。否则规则写错一次，你自己把站点封死了——这比不防还惨。

---

### 3. "爬取网站代码"是个错觉

**原话**：「能够爬取网站代码」「爬取网页」

**症状**：这两个词说的是完全不同的事，需求里混着用。

- 爬网页 = 拿到 HTML/JS/CSS/JSON，**看不到服务端源码**。
- 拿到服务端源码 = 需要源码泄露漏洞（`.git` 暴露、备份文件、source map），
  属于"撞上了"，不是"爬"出来的。

**后果**：如果按字面理解，学生会以为"爬到了 HTML 就等于拿到了源码可以静态分析"，
最后做出来的东西是"下载几个页面然后正则匹配报错信息"。

**对策**：明确拆成两层：
1. **爬取攻击面**：URL、表单、参数、Cookie、JS 里的接口字面量、响应头。
2. **分析**：被动规则（配置/泄露/指纹）+ 主动 PoC（真实注入验证）。

真要做代码审计，那得是**另一个项目**（源码 SAST），别塞进来。

---

### 4. 两个课题硬合并 = 工作量翻倍，深度减半

课题 30 是扫描器，课题 54 是一整套 SOC 式监控响应（日志采集、智能分析、分级告警、
响应模板、溯源）。两个都完整做，学生项目的体量撑不住。

**后果**：最后两边都是半成品：扫描器只有 3 条规则，监控只有一个 `tail -f` 加两个正则。
报告写得漂亮，演示一碰就露。

**对策**：砍到"两个都够深"的最小集：
- 扫描：被动规则做全（这套最稳、零误报）+ 4 类主动 PoC（XSS/SQLi/LFI/开源跳）做深
- 监控：4 类攻击检测 + 事件聚合 + 双通道告警 + 代理级阻断 + 可回滚
- 其余全部列进"v1 不做"（见大纲第 12 节），显式声明比偷偷缺更强

## 🟠 重要级：不致命，但答辩会被追着问

### 5. 健康评分没有定义

"输出健康评分"——**80 分是怎么算出来的？** 如果答不上来，这个功能就是装饰品。

对策：给出确定性、可复算的公式（noisy-OR，见大纲第 6 节），
并且报告里列出每一条扣分明细。评分必须能从 findings 完全重算出来。

---

### 6. 没规划误报率

签名式扫描器的误报是**海量**的，尤其"版本号匹配 CVE"这种。
一个满屏红色的报告，老师第一反应就是"这不准吧"。

对策：
- 每条 finding 必须有 evidence（原始请求/响应报文 + 复现步骤）
- 主动检测必须"二次验证"（再发一次能否复现），time-based 类必须做统计基线
- 内置"误报标记"功能，误报样本回流成规则的白名单
- 评测时专门跑一次"无漏洞站点"，报出误报率数字

---

### 7. 爬虫的范围、状态、陷阱都没设计

真实的坑：
- 爬到 `/logout` → 把自己会话踢掉，后面全扫空
- 爬到 `/delete?id=1` → 把人数据删了（GET 也能改数据的老系统很多）
- 日历/分页 URL 无限生成（`?date=...` 每天一个）
- 登录后的页面爬不到（没有会话维持机制）
- SPA 站点爬出来只有 1 个 URL（内容全在 JS 里）

对策见大纲 4.2。**爬虫必须先限速、限深、限域、排除破坏性路径**，再谈分析。

---

### 8. 现代站点用纯 HTTP 爬虫基本抓不到东西

React/Vue 的站点，`httpx.get()` 拿回来的 HTML 里可能只有一个 `<div id="root">`。
靶场如果用 OWASP Juice Shop（Angular SPA）演示，纯爬虫会当场翻车。

对策：准备两条爬取路径（静态 + Playwright 渲染），默认静态、按需渲染；
并且**尽早用真实靶场验证**，别等到 W4 才发现。

---

### 9. 日志采集的"量"没算过

`tail -f` 在 demo 时很美好，实际会遇到：
- 日志轮转（`.log` → `.log.1`）后文件句柄失效，从此静默丢日志
- 大流量下解析跟不上 → 内存里堆积 → 要么卡死要么丢
- 多行日志（栈追踪）被拆成多条，规则全废

对策：采集器实现"偏移量持久化 + 轮转检测 + 有界队列（满了计数丢弃并告警）"，
解析器支持多行合并。这些在报告里都算"工程细节"，写进去就是分。

---

### 10. 告警会变成骚扰（告警风暴）

一次 SQL 扫描器扫你的站，可能触发 200 条告警。没有聚合 = 邮箱被刷爆 = 用户关掉告警 =
监控等于没做。

对策：聚合键 `(规则, 源IP, 目标)` + 时间窗 + 抑制期 + 分级推送节奏（高危即时、
中危 5 分钟聚合、低危每日摘要）。见大纲 5.4/5.5。

---

### 11. 阻断的副作用完全没提

- IP 封禁会误伤 NAT/代理后面的一整片正常用户
- 自动封禁逻辑有 bug 时，可能把自己的办公室 IP 段封掉
- 封完没解封机制 = 手动清 iptables
- Windows 上改防火墙要管理员权限，双击 exe 直接失败

对策：TTL + 白名单 + 上限 + 一键回滚 + fail-open + 优先在**应用层**（代理模式）封，
不碰系统防火墙，这样跨平台又不需要提权。

---

### 12. "异常情况"没有枚举

需求说"出现异常情况或高风险情况即时告警"，但**什么叫异常？** 不说清楚，
实现时就是一堆拍脑袋的 if。

对策：把可观测信号列全：
可用性（探活失败连续 N 次）、性能（响应时间 p95 超基线 3 倍）、
错误率（5xx > 20%）、内容（页面哈希变化 = 可能被篡改）、证书（30 天内到期）、
流量（单 IP 速率突增）、攻击特征（规则命中）。
每一条都要能落到"哪个采集器 + 哪条规则 + 哪个阈值"。

---

## 🟡 次要级：合规与产品化

### 13. 授权边界没做成产品特性

输入任意网址就能扫，这个产品形态本身就危险。别只写一句"请确保已获授权"的弹窗——
弹窗谁都会点"确定"。

对策：资产必须绑定授权记录（靶场白名单 / 自建 / 书面授权），
扫描任务强制关联 asset_id，审计日志留痕。这是设计亮点不是负担。

---

### 14. 软件自身的安全没考虑

- 存了目标站点的登录凭据 → 明文落盘 = 送人头
- 报告里有 Cookie/token → 导出即泄露
- Web UI 如果监听 `0.0.0.0` → 你给别人送了个远程控制面板

对策：凭据用操作系统密钥环或 Fernet 加密；报告导出前做敏感字段脱敏；
服务默认只绑 `127.0.0.1`；不做任何遥测上报。

---

### 15. 短信告警不现实

需求列了"弹窗、短信、邮件、系统消息"。短信要买通道、要实名、要钱。

对策：邮件 + Webhook（钉钉/飞书/Server酱）+ 站内弹窗全覆盖，短信做成适配器接口
+ Mock 实现，报告里说明"生产环境接入阿里云短信只需替换 adapter"。

---

### 16. 没有"可复核性"设计

安全报告最怕"说了有漏洞但证明不了"。没有证据链，老师随便挑一条问"你怎么确定"，
就答不上来。

对策：finding 与 evidence 一对一，evidence 存原始报文（脱敏后）+ 哈希 + 复现步骤，
报告里每条都能点开看。

---

## 附：需求-设计对照表

| 原需求 | 落地方式 | 风险点 |
| --- | --- | --- |
| 输入网站自动扫描 | 资产准入 + 爬虫 + 规则引擎 | 未授权、爬虫失控 |
| 爬取网站代码 | 只爬攻击面，不做源码审计 | 概念误解 |
| 漏洞分析 | 被动规则 + 主动 PoC + 二次验证 | 误报 |
| 健康评分 | noisy-OR 可复算模型 | 无可解释性 |
| 长期挂站持续扫描 | **改为**代理/日志接入的被动监控 | 原方案不可行 |
| 异常即时告警 | 规则 + 基线 + 聚合分级 + 多通道 | 告警风暴 |
| 应急阻断（可开关） | 代理层拦截 + IP 封禁 + 回滚 | 无阻断点、误封 |
| 全量日志采集 | 采集适配器 + 归一化 | 轮转/背压 |
| 智能分析 | 规则 + 窗口统计 + 简单基线 | 复杂度 |
| 分级告警 | 高/中/低 → 渠道与节奏映射 | 短信成本 |
| 应急响应模板 | 结构化 YAML + 执行记录 + 版本 | 容易写成文档摆设 |
| 溯源 | incident 时间线 + 会话聚合 + 审计 | 数据不足时无意义 |
| 模板优化 | 处置记录回流模板版本 | 易遗漏 |
